# 鲜知真实语音回归样本

将下列原句转成解析、对话状态和副作用的独立断言。不要只断言最终播报文字。

## 输入补全与数量

- `我中午买了` → 保留新增候选，询问食材和数量。
- `三个苹果` → 续接为 `添加3个苹果`，确认后只写入一次。
- `帮我添加一下两百克生菜` → `添加200克生菜`，不把“一下”写成数字。
- `添加两块鸡胸肉` → 2 片/块鸡胸肉是合理单位。
- `半斤的鸡胸肉` → 0.5 斤，确认变体 `是的对`、`对的确认` 都能执行。

## 别名、纠错与位置

- `两颗皮蛋` → 皮蛋；不得误识别为鸡蛋。
- `五百克的巴沙` → 巴沙鱼。
- `一瓶红酒`、`四斤冷冻的香肠` → 可识别的新增候选；冷冻需映射到家庭冷冻区。
- `不是鸡蛋是鸭蛋` → 替换单项候选，不追加鸡蛋与鸭蛋两项。

## 读操作与结束

- `我想吃土豆牛腩还要买什么` → 只读菜谱缺料核对，不触发消耗。
- `我今天下午想吃个下午茶，冰箱里有什么可以推荐` → 识别为只读加餐建议，给出一份具体方案，不重复库存清单，也不扣减库存。
- `明天中午十二点把苹果吃了` → 12:00 的提醒确认，不把 `8个` 或其它数字当时间。
- `结束对话谢谢`、`好谢谢结束`、`好的谢谢结束`、`结束兑换` → 取消当前候选，回到仅唤醒词待机。
- 助手自己的 TTS 和环境音在待机/播报期不能创建新的语音任务。

## 餐食承接、多人菜单与存放移动

- `我想要一个少油少盐的食谱`、`继续刚才的食谱` → 延续为只读餐食建议，不能落入“动作、食材和数量”库存提示。
- `晚上六个人吃饭，按冰箱食材推荐几道菜`、`周末朋友来聚会` → 返回多道菜的菜单、人数份量边界与缺料；不得只重复一道菜，也不得把人数当消耗数量。
- `把所有猪肉移到冷冻室`、`冷藏室的猪肉移到冷冻室` → 生成 `MOVE_INVENTORY` 候选，列出匹配在库批次并确认；不得新增、消耗或只口头说“已更新”。
- 浏览器 VAD 遇到自然停顿时必须保留句尾；“少油少盐”“六个人”“移到冷冻室”等补充信息不得在中途提交前被截断。
- `还有几个苹果`、`把猪肉移到冷冻室`、`对`、`结束对话` → 本地工具或状态机处理，断言没有外部模型调用。
- `按我家的库存给六个人推荐周末菜单`、`根据我的减脂目标推荐下午茶` → 进入个性化 Agent；输入包含库存、人数、成员授权偏好和近期推荐，输出不能引用不存在的库存食材。
