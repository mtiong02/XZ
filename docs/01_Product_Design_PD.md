## 1. 产品愿景

XZ 要成为家庭的 Food OS：以真实食材库存和真实饮食行为为基础，通过手机、平板、电脑和未来 AI 冰箱贴，逐步连接食材管理、浪费减少、用餐记录、营养计算、健康指标和个性化饮食建议。

当前 MVP 不承担完整健康管理职责。它要先证明两个底层假设：

1. 用户愿意通过语音或手动操作持续维护数字冰箱；
2. 系统能把用户表达安全、准确地转换成可追踪的库存事实，并在多终端实时同步。

## 2. 产品定位

> XZ 是一个硬件就绪、健康扩展就绪的 AI 数字冰箱系统。当前用户通过手机、iPad 或电脑进行语音和手动操作；未来可通过吸附在冰箱外部的 AI 玩偶冰箱贴直接对话。

### 2.1 当前价值

- 看清冰箱里有什么、剩多少、什么时候过期；
- 用一句话添加、使用、丢弃或查询食材；
- 多个终端和家庭成员看到同一份最新库存；
- 临期食材得到及时提醒；
- 所有变化有来源、有记录、可撤销。

### 2.2 未来价值

- 将食材使用组织为菜品与份量；
- 记录家庭成员实际摄入；
- 计算卡路里和宏量营养素；
- 接入体重、血压、血糖、血脂等健康指标；
- 由受控 AI Agent 生成饮食规律总结、风险提示和个性化建议；
- 接入自动补货、家庭照护和碳减排报告。

## 3. 关键术语

| 术语     | 定义                                                           |
| -------- | -------------------------------------------------------------- |
| 数字冰箱 | 对真实家庭冰箱库存的数字化表达，不宣称传感器自动感知全部实物。 |
| 库存批次 | 同一种食材在不同时间加入、具有独立数量和到期日的一组库存。     |
| 库存使用 | 食材离开库存，可能用于做饭、分享或其他用途，不等于某个人吃了。 |
| 个人摄入 | 明确归属于某个家庭成员的实际食用记录。                         |
| Meal     | 由一种或多种食材组成的菜品或一餐，可产生多个份量。             |
| 事实     | 用户确认或确定性系统计算的数据。                               |
| AI 洞察  | 模型基于事实生成的推断或建议，不等同于医学事实。               |
| Channel  | 操作入口，例如 WEB_MANUAL、MOBILE_VOICE、FRIDGE_MAGNET_VOICE。 |

## 4. 用户与核心场景

### 4.1 核心用户

1. 双职工年轻家庭：需要减少浪费和晚餐决策负担。
2. 独居或合租青年：购买份量难控制，容易忘记库存。
3. 关注父母饮食的成年子女：未来需要家庭共享和远程健康照护。

### 4.2 当前 MVP 关键场景

#### 场景 A：语音添加

用户说：“刚买了两盒牛奶和十个鸡蛋。”

系统：

1. 录音并识别文本；
2. 解析为 ADD_INVENTORY；
3. 展示牛奶 2 盒、鸡蛋 10 个；
4. 用户确认或修改；
5. 创建库存批次；
6. 所有在线终端同步更新。

#### 场景 B：语音使用

用户说：“午饭用了两个鸡蛋和一个西红柿。”

系统默认解释为库存使用，不记为个人摄入。确认后优先扣减最早到期批次。

#### 场景 C：手动修正

用户发现鸡蛋实际还有 5 个，打开鸡蛋详情并执行“修正库存”。系统必须保留修正前后值、理由和操作者。

#### 场景 D：临期提醒

系统发现牛奶次日到期，首页置顶并发送提醒。用户可直接执行“已使用”“已丢弃”“延后确认”。

#### 场景 E：多端同步

用户在手机确认使用两个鸡蛋，打开中的 iPad 和电脑在 1 秒内看到同一库存变化与活动记录。

## 5. MVP 目标与非目标

### 5.1 MVP 目标

- 完成数字冰箱与库存批次管理；
- 支持语音和手动两种输入；
- 支持添加、使用、丢弃、修正、查询、撤销；
- 支持手机、iPad、电脑响应式使用；
- 支持家庭内实时同步；
- 支持临期状态与基础提醒；
- 建立可审计的库存交易和语音任务记录；
- 建立未来硬件、营养、健康和 AI Agent 的稳定扩展契约。

### 5.2 MVP 非目标

- 不开发真实冰箱贴硬件、配网、MQTT 或 OTA；
- 不自动感知真实冰箱内全部食材；
- 不把库存减少自动等同个人摄入；
- 不提供医学诊断、治疗方案或药物建议；
- 不完成体检报告解析、穿戴设备同步或完整营养报告；
- 不接入自动电商下单；
- 不做社区、积分、家庭 PK；
- 不做全天候语音监听或声纹识别。

## 7. 详细交互要求

### 7.1 数字冰箱首页

必须显示：

- 食材总数、临期数量、过期数量；
- 冷藏、冷冻、常温分区；
- 食材名称、图标、剩余量、单位、最早到期日；
- 临期状态；
- 快速手动操作；
- 固定语音入口。

### 7.2 语音状态机

```text
IDLE
  -> RECORDING
  -> UPLOADING
  -> TRANSCRIBING
  -> PARSING
  -> AWAITING_CONFIRMATION
  -> EXECUTING
  -> COMPLETED
```

异常状态：

```text
AUDIO_TOO_SHORT
AUDIO_TOO_NOISY
ASR_FAILED
AMBIGUOUS_COMMAND
VALIDATION_FAILED
INSUFFICIENT_INVENTORY
EXECUTION_FAILED
```

### 7.3 确认卡片

任何库存写操作必须显示：

- 原始识别文本；
- 动作类型；
- 食材、数量、单位；
- 受影响库存的变更前后；
- 修改、取消、确认按钮。

危险操作需要强确认：

- 全部丢弃；
- 清空库存；
- 数量明显异常；
- 单位无法确认；
- 多批次歧义；
- 系统置信度低于阈值。

### 7.4 食材详情

必须显示：

- 总剩余量；
- 各库存批次；
- 添加时间、到期时间、来源；
- 使用、丢弃、修正记录；
- 最近一次变化；
- 撤销或修正入口。

## 8. 业务规则

1. 数量不得为负。
2. 默认使用 FEFO：先扣最早到期批次。
3. 所有库存变化必须通过交易流水产生。
4. 删除历史记录不允许直接物理删除；使用撤销或纠正交易。
5. 丢弃与使用必须分开记录。
6. 操作者不等于食用者。
7. 个人摄入只有用户明确表达并确认后才能记录。
8. 到期日来源必须标识：用户输入、包装 OCR、规则估算、未知。
9. AI 估算值不得伪装成用户确认事实。
10. 同一 idempotency key 只执行一次。

## 10. 成功指标

### 10.1 北极星指标

**每个家庭每周成功完成的库存更新次数。**

### 10.2 MVP 指标

| 指标                 |    目标 |
| -------------------- | ------: |
| 首次任务完成率       |  >= 80% |
| 语音任务完成率       |  >= 85% |
| 单食材意图准确率     |  >= 95% |
| 食材实体准确率       |  >= 90% |
| 数量准确率           |  >= 90% |
| AI 结果修改率        |  <= 15% |
| 每户每周有效库存操作 | >= 5 次 |
| 7 日留存             |  >= 35% |
| 临期提醒后产生操作   |  >= 40% |
| 重复扣减             |       0 |
| 负库存               |       0 |

## 11. 未来健康功能的产品约束

- 健康数据必须按成员隔离和授权；
- 用户可以撤销授权并删除数据；
- 任何建议必须说明数据依据、时间范围和局限；
- AI 建议与医学诊断之间必须明确区分；
- 缺失摄入数据时不得生成精确卡路里结论；
- 体重、血压、血糖等数据需要来源和测量时间；
- 推荐应支持“减脂、高蛋白、低糖、过敏、口味、预算、时间”等约束，但规则层先过滤，LLM 再解释。

## 12. 发布准入

MVP 可进入种子测试的条件：

- P0 功能验收通过；
- 重复扣减、越权访问和负库存测试全部通过；
- 手机、iPad、电脑主流程可用；
- 语音测试集达到最低准确率；
- 原始音频默认 24 小时清理；
- 监控、错误追踪和审计记录可用；
- 已完成隐私说明与用户确认文案。
