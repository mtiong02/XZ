# 食材百科与家庭营养结构执行计划

## 1. 产品定位

食材百科是可检索的通用食材知识，不是要求用户手工维护的后台目录。家庭营养结构是基于当前活动库存的确定性分析；小知营养管家负责把分析转成用户能执行的建议，但不把库存事实、个人摄入和医疗结论混在一起。

```text
食材百科（通用事实）
        + 家庭偏好与储存条件
        + 成员健康档案（按授权）
        + 当前库存事实
        ↓
家庭营养结构（规则分析）
        ↓
小知建议（解释、菜谱、补充和提醒候选）
```

## 2. 已完成的第一阶段

- 增加 `GET /api/v1/households/:householdId/nutrition/structure`。
- 按专业食材分类聚合蛋白质、蔬菜、水果、主食、奶类、豆类、坚果/脂肪、海鲜等结构分组。
- 输出缺口观察、证据食材、库存版本和营养资料完整度。
- 当营养资料缺失时降级为类别级分析，不计算精确热量或减重结果。
- 食材百科改为搜索优先；自定义食材表单收进“找不到食材时”的折叠入口。
- 首页展示家庭营养结构摘要，餐食页显示结构缺口，语音查询餐食时引用结构分析。

## 3. 后续迭代顺序

### P1：权威营养资料

- 为常用标准食材接入可追溯的营养资料来源。
- 每条资料必须包含来源、基础计量单位、核验时间和适用条件。
- 没有来源的数据不得填入；不同来源冲突时显示“不确定”，不能静默覆盖。
- 只有资料完整度达到阈值时，才允许展示宏量营养素级别的估算。

### P1：家庭画像

- 记录国家/地区、时区、常见菜系、常用单位、储存设备和家庭忌口。
- 家庭画像只影响推荐和展示，不覆盖标准食材事实。
- 包装说明和用户确认优先于百科默认保存规则。

### P2：成员个性化

- 沿用 `member_wellness_profiles` 的权限边界，成员健康数据默认仅本人可见。
- 结合成员目标、过敏原、饮食限制和可授权的健康信息生成个人视图。
- 家庭结构分析与成员建议分开显示，避免把家庭库存误认为个人摄入。

### P2：小知营养管家

- Agent 默认只读，调用库存查询、食材百科、营养结构和菜谱工具。
- 创建提醒、加入购物清单或修改库存时生成候选并要求确认。
- 每条建议展示依据、时间范围、可信度和局限。
- AI 服务不可用时，库存、百科、规则分析和手动餐食功能仍可用。

### P3：真实摄入与营养快照

- 引入 Meal、份量和成员摄入事实后，才能计算个人摄入趋势。
- 摄入记录与库存消耗必须分开保存；库存减少不自动推断谁吃了多少。
- 计算结果保存数据来源、版本和快照时间，支持撤销和审计。

## 4. 验收标准

- 用户添加库存时优先搜索标准食材，找不到时才创建家庭自定义食材。
- 家庭首页和食材百科显示同一库存版本的结构分析，不出现数据分叉。
- 至少覆盖蛋白质、蔬菜、水果、主食四个核心类别，并能提示缺口。
- 每个分析结果能回溯到食材分类或营养资料；没有资料时明确显示数据不完整。
- 不生成“营养达标”“适合治疗”“保证减重”等医疗或效果性结论。
- 家庭成员未授权时，其他成员不能看到其健康档案和体重数据。
- 规则层、API、UI 和语音路径均有测试；外部 AI 故障不阻止基础库存操作。

## 5. 当前未完成项

当前版本已经完成库存结构分析和产品入口，但还没有接入经过授权的完整营养数据库，也没有把个人实际摄入纳入计算。因此现阶段的“健康/合理”只能解释为“库存类别结构是否均衡、是否存在明显缺口”，不能替代营养师或医疗判断。
