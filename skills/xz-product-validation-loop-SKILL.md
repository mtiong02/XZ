# XZ Product Validation Loop

## 适用范围

用于小知验证期的语音、餐食决策、库存和购物清单改动。目标是保持一个可重复、可审计的日常闭环，而不是扩展功能数量。

## 固定工作流

1. 先从真实对话或指标确认问题，写出可观测的失败场景。
2. 判断问题属于 ASR/端点检测、轮次协调、确定性规则、上下文构建、AI 推理还是界面确认。
3. 只改动对应层；不得用大模型掩盖库存事实、权限或状态机错误。
4. 为每个改动补充一个回归样例和一个事件指标。
5. 运行 API typecheck、Web typecheck、全部 API 测试和生产构建。
6. 部署后检查 `/api/v1/health`、首页 HTTP 200、容器状态和验证指标接口。
7. 用 15–20 户试点数据决定下一步：保留、修复或暂停。

## Agent 约束

- 查询不需要确认；生成菜单和购物草稿不需要强确认；写入购物清单需要软确认；外部下单必须强确认。
- 事实（库存、数量、保存区、过期日）与偏好（口味、常做菜、忌口倾向）分开存储。
- 结束表达应回到唤醒待机；普通环境声不能创建新任务。
- 同一家庭成员同一时间只允许一个有效任务；新任务必须取消旧任务并记录事件。
- 推荐只能使用上下文提供的食材；缺少的调味料必须显式列为缺料。
- 任何 telemetry 失败都不能阻塞库存、提醒或语音响应。

## 交付检查

- [ ] 真实对话样例加入测试
- [ ] 事件类型和指标定义同步
- [ ] 无原始敏感信息进入 metadata
- [ ] 失败可回退到确定性结果
- [ ] 部署后健康检查通过
